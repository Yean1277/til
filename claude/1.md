# Claude Code 高级用法 · 2026 整理

## 一、四层架构思路（核心心法）

把 Claude Code 当**可编程平台**，而不是聊天框。很多人卡在第三、第四个工作流，原因都是「在错误的层里用对的工具」——本该写成 hook 的行为约束被塞进 system prompt，本该做成 skill 的可复用流程被反复粘贴到对话里 [Substack](https://boringbot.substack.com/p/claude-code-skills-subagents-hooks) 。

四层各司其职：
- **CLAUDE.md** — 规则与项目记忆
- **Skills** — 可复用的工作流程
- **Hooks** — 确定性强制执行
- **Subagents** — 上下文隔离与并行

## 二、CLAUDE.md 七条铁律

先跑 /init 让 Claude 从代码库生成基线再去修剪，永远不要从零开始；保持在 200 行以内（太长会被忽略，Claude 大约可靠遵循 150 条指令）；用 hooks 做 100% 强制（CLAUDE.md 只是建议性的，遵循率约 70%）；用 @imports 模块化；配合 /compact 和 plan mode；每月更新——Claude 每犯一次错就加一条规则 [Obvious Works](https://www.obviousworks.ch/en/designing-claude-md-right-the-2026-architecture-that-finally-makes-claude-code-work/) 。

`@docs/git.md` 这种切分写法是 2026 年的新模式，作用域清晰、跨项目可复用。

## 三、Skills：可调用的工作流

把同一套指令教 Claude 一次，之后用名字直接调用——便签变成 slash 命令。和每次对话粘指令不同，skill 只在需要时加载，不污染上下文 [Medium](https://medium.com/@mishra.shashank35/claude-code-skills-subagents-hooks-and-plugins-a-practical-overview-572de7cedb20) 。

Skills 在 SKILL.md 里定义，老的 .claude/commands 文件仍然兼容，同名时 skill 优先。Skills 可以在 fork 的 subagent 上下文里运行（context: fork），内置的 /batch skill 用隔离的 git worktree [RanketAI](https://www.trensee.com/en/blog/explainer-claude-code-skills-fork-subagents-2026-03-31) 。

## 四、Hooks：不可妥协的强制层

Hooks 确保 Claude 在你没盯着的中途也守规矩。Skills 是你主动调用的，hooks 是隐形的，自动跑——这就是重点。目前大约有 24 个 hook。适合定不可商量的事项：永远不读 .env、提交评论前要确认、记录每次工具调用做审计 [Medium](https://medium.com/@mishra.shashank35/claude-code-skills-subagents-hooks-and-plugins-a-practical-overview-572de7cedb20) 。

作用域取决于 settings.json 的位置：项目级 hook 适合团队共享策略，`~/.claude/` 下的个人 hook 全局生效。

## 五、Subagents：并行与上下文隔离

Agent teams 是主 agent 协调下的专业化 subagents，每个有自己的上下文窗口、prompt 和工具权限。主 agent 负责规划和整合，专业 subagent 处理有边界的任务（代码评审、跑测试、前端 QA、安全检查）。任务能自然拆成不同工具需求的专门职责时就用 subagent——比如 checkout 重构可以拆出 backend、frontend、test、review 四个 [Developers Digest](https://www.developersdigest.tech/blog/claude-code-agent-teams-subagents-2026) 。

关键洞察是并行执行：独立任务批量启动，不要串行跑 [BSWEN](https://docs.bswen.com/blog/2026-04-09-subagents-skills-claude-code/) 。

## 六、Plugins：把这些打包分享

Plugin 把 skills、hooks、subagents、tools 一起打包——团队不用每个人手动配同一套，一键安装。Skills 和 hooks 是给你或项目用的，plugins 是用来分享的。通过 marketplace 分发：GitHub 仓库、npm 包、或团队内部 registry。Plugin 的 skill 自动加命名空间（/security:scan）避免和本地冲突 [Medium](https://medium.com/@mishra.shashank35/claude-code-skills-subagents-hooks-and-plugins-a-practical-overview-572de7cedb20) 。

## 七、2026 新出的实用命令与模式

- **`/compact`** — 把上下文压到 50% [Obvious Works](https://www.obviousworks.ch/en/designing-claude-md-right-the-2026-architecture-that-finally-makes-claude-code-work/) ，长会话续命神器
- **Plan mode** — 3 步以上的任务先规划再执行
- **`/goal`** — 跨多轮一直工作，直到完成条件满足为止 [Claude](https://code.claude.com/docs/en/whats-new)
- **`claude agents`** — 一屏看完所有 Claude Code 会话：在跑的、等你的、已完成的 [Claude](https://code.claude.com/docs/en/whats-new)
- **Rewind 菜单的 "Summarize up to here"** — 压缩历史上下文
- **`/powerup`** — 交互式新功能教程 [Apiyi.com Blog](https://help.apiyi.com/en/claude-code-changelog-2026-april-updates-en.html)

## 八、选层决策表

| 需求 | 用哪层 |
|---|---|
| 项目背景、约定 | CLAUDE.md |
| 重复的工作流（PR review、部署检查） | Skill |
| 不可违反的规则（禁读 .env、强制 lint） | Hook |
| 上下文太挤 / 需要并行 | Subagent |
| 团队共享整套配置 | Plugin |

## 九、起步建议

从 skills 开始——最容易做，立竿见影。需要确定性强制时加 hooks。并行或上下文隔离重要时用 subagents [DEV Community](https://dev.to/owen_fox/claude-code-hooks-subagents-and-skills-complete-guide-hjm) 。
